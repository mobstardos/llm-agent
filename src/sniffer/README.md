# Universal Sniffer v3.1

Универсальный TCP-прокси сниффер с живой веб-панелью, разбором протоколов,
экспортом в JSONL / SQLite / PCAP / CSV и настраиваемыми тревогами.

Развитие идеи `multi_sniff.py`: тот же сценарий «АЗС подключаются к старым
портам — сниффер проксирует трафик на новые порты сервера и всё показывает»,
но универсально: любые порты, автодетект протоколов, плагины, веб-интерфейс,
экспорт для Wireshark и аналитики.

Только стандартная библиотека Python — **ноль внешних зависимостей**.
Работает на Windows 7/10/11 и Linux (Python 3.7+).

## Запуск без Python: exe-сборки

Три способа получить готовое исполняемое приложение:

**1. Портативная сборка (рекомендуется)** — архив `UniversalSniffer-win64-portable.zip`.
Распакуйте целиком в любую папку и запустите `UniversalSniffer.exe` — откроется
консоль и браузер с веб-панелью. Внутри архива: официальный встраиваемый Python 3.11
(`runtime\`), исходники сниффера (`app\`) и нативный лаунчер с иконкой. Ничего не
устанавливает и не требует прав администратора. Конфиг, панель и данные находятся
рядом с exe: `config.json`, `capture\`, `app\plugins\`. Запасной запуск — `UniversalSniffer.bat`.

**2. Одиночный exe через PyInstaller** — на любой Windows-машине с Python 3.9+
запустите `builder\build_exe.bat` (двойной клик). Скрипт сам создаст изолированное
окружение, поставит PyInstaller и соберёт `dist\UniversalSniffer.exe` — один файл
(~12 МБ) с веб-панелью и иконкой внутри. Запуск: `UniversalSniffer.exe --help`.
Конфиг и `capture\` создаются рядом с exe; на Linux/macOS то же самое делает
`builder/build_exe.sh`. Вся конфигурация сборки — в `builder/sniffer.spec`.

**3. Автоматическая сборка в облаке** — `.github/workflows/build_exe.yml`.
Выложите проект на GitHub — Actions соберёт `UniversalSniffer.exe` при каждом
push (артефакт во вкладке Actions), а на тегах `v*` приложит exe к Release.

Сравнение: портативная сборка стартует мгновенно и правится «на живую» (исходники
рядом), но занимает папку; PyInstaller-exe — один переносимый файл, но при каждом
запуске распаковывается во временный каталог. Функциональность одинаковая.

## Служба Windows: автозапуск

Сниффер можно установить как службу Windows — будет стартовать при загрузке
машины, работать без консольного окна и автоматически перезапускаться при
сбоях (через 5/30/60 с). Сторонних зависимостей нет: работа со службами
выполняется напрямую через advapi32 (ctypes).

Управление (запускайте от имени администратора):

```
UniversalSniffer.exe --service install     # установить службу (автозапуск)
UniversalSniffer.exe --service start       # запустить
UniversalSniffer.exe --service status      # состояние
UniversalSniffer.exe --service restart     # после правки config.json
UniversalSniffer.exe --service stop        # остановить
UniversalSniffer.exe --service remove      # удалить службу
```

- В портативной сборке то же самое делает **`service.bat install`**
  (сам запросит права администратора) или `UniversalSniffer.exe --service install`.
- Служба называется `UniversalSniffer`; при установке запоминается команда
  запуска с путями к exe и `config.json`, поэтому конфиг и `capture\`
  остаются рядом с программой.
- Логи службы: `capture\service.log` (консоли у службы нет).
- Веб-панель доступна по прежнему адресу (`http://127.0.0.1:9500/`).
- Сменили порты в `config.json` — выполните `--service restart`.
- Если порт занят другим приложением, служба не сможет слушать его —
  проверьте `netstat -ano | findstr :9000` и поправьте конфиг.
- Удаление службы сначала мягко останавливает сниффер, затем убирает запись.

На Linux автозапуск оформляется через systemd — см. раздел 11.

## 1. Быстрый старт

### Сценарий с АЗС (замена multi_sniff.py)

1. Остановите RemoteServer.
2. Запустите RemoteServer на портах-преемниках: TCP 3004, Thrift 10011.
3. Запустите сниффер с портами АЗС:
   - **Windows:** двойной клик по `run_windows.bat` или `py -3 sniffer.py`
   - **Linux:** `./run_linux.sh` или `python3 sniffer.py`

```
py -3 sniffer.py --ports 3003:3004,10010:10011
```

4. АЗС продолжают подключаться к 3003 и 10010 как обычно.
5. Откройте веб-панель: **http://127.0.0.1:9500/**

Порты по умолчанию заданы в `config.json` (9000→9001, 9010→9011, панель 9500)
и подходят для универсального мониторинга; для сценария АЗС укажите порты
ключом `--ports` (пример выше) или прямо в конфиге — все способы в разделе 7.

### Что вы увидите

- **Консоль** — цветной поток пакетов, подключения/отключения, тревоги.
- **Веб-панель** (порт 9500) — живая таблица трафика, фильтры, графики,
  сессии, тревоги со звуком, hex-дамп каждого пакета, скачивание файлов захвата.

## 2. Консоль

```
[12:31:07.412] -> 10.8.0.51:41234 [RemoteServer TCP] REMOTE_SERVER  DB_REQUEST (C=200,D=100) S=1043 TX=8821  1.4KB
[12:31:07.428] <- 10.8.0.51:41234 [RemoteServer TCP] REMOTE_SERVER  DB_REQUEST (C=200,D=100) S=1043 TX=8821 zlib  18.7KB
[12:31:09.031] <- 10.8.0.51:41240 [Thrift RPC] THRIFT  REPLY sendTanksState seq=57 [SEND_TANKS_STATE]  512B
[12:31:10.884] !! ТРЕВОГА [CRIT] Thrift EXCEPTION — EXCEPTION onConnect seq=12
```

- `->` зелёным — TX (клиент → сервер), `<-` синим — RX (сервер → клиент).
- Тревоги — жёлтым/красным, автодетект протокола — жёлтым.

Уровни детализации (`--verbosity` / `console.verbosity`):

| уровень  | что выводится |
|----------|---------------|
| `quiet`  | только подключения и тревоги |
| `summary`| по строке на пакет |
| `full`   | строка + таблицы БД + строки данных + поля Thrift |

## 3. Веб-панель

Открывается на `http://<адрес-сниффера>:9500/`. Разделы:

### Поток
Живая таблица пакетов (SSE, без перезагрузки страницы):

- **Фильтры без перезапуска**: текстовый поиск, протокол, команда/метод,
  клиент, направление TX/RX, диапазон размера, только валидные.
- **Пауза** — поток замирает, события копятся в буфере (до 3000) и
  досыпаются при возобновлении.
- Клик по строке — **детали пакета**: все распознанные поля, поля Thrift,
  hex-дамп + ASCII-вид.

### Статистика
- График пакет/секунду (последние 5 минут).
- Распределение по протоколам, топ команд/методов, активность клиентов,
  счётчики по каналам перехвата.

### Сессии
Активные TCP-соединения: клиент, канал, цель, время старта, TX/RX пакеты и
байты, состояние, распознанный протокол.

### Тревоги
Журнал срабатываний с важностью. Критические тревоги сопровождаются
звуковым сигналом (отключается кнопкой «звук»).

### Настройки
- Кнопка **«Перечитать config.json»** — применяет правила тревог, уровень
  консоли и настройки экспорта без остановки сниффера.
- Кнопка **«Сформировать CSV-отчёты сейчас»**.
- Скачивание `traffic.jsonl`, `traffic.pcap`, `traffic.db` прямо из панели.
- Список загруженных парсеров и просмотр текущего конфига.

## 4. Протоколы и автодетект

На каждом направлении соединения сниффер определяет протокол по первым
байтам и выбирает парсер с максимальной уверенностью:

| протокол       | сигнатура | что извлекается |
|----------------|-----------|-----------------|
| RemoteServer TCP | magic `AA AA 00 00` в заголовке 9 байт | версия, zlib-распаковка, RequestCmdClass/RequestCmd → тип команды, SessionNum, TransactionID, таблицы БД |
| Thrift RPC | framed-транспорт, binary protocol | CALL/REPLY/EXCEPTION/ONEWAY, имя метода, seq, класс метода (cashless, syncData…), **поля аргументов (строки, числа)** |
| HTTP | `GET/POST/...`, `HTTP/1.` | метод, путь, код, заголовки, JSON-тело |
| JSON | `{`/`[` | ключи, метод/действие, id |
| Modbus TCP | MBAP proto=0 | функция, адрес регистра, количество, значения, исключения |
| RAW/Hex | всё остальное | hex-дамп, печатные строки, доля бинарных данных |

Особенности:

- **Частичные кадры.** TCP не гарантирует границ сообщений — фреймеры
  накапливают данные и отдают только целые кадры (в оригинале `multi_sniff.py`
  каждый `recv()` считался пакетом, из-за чего крупные Thrift-фреймы
  разваливались).
- **Прозрачный режим.** Если поток не соответствует протоколу, канал
  продолжает работать в прозрачном режиме (данные ретранслируются,
  пишется RAW с hex-дампом). Разбор никогда не мешает передаче.
- **Независимые направления.** TX и RX детектируются отдельно (например,
  HTTP-запрос + JSON-ответ).

## 5. Экспорт данных

| файл | что содержит | чем открыть |
|------|--------------|-------------|
| `capture/traffic.jsonl` | построчный JSON каждого пакета (с ротацией 50 МБ, 5 копий) | любой текстовый редактор, jq |
| `capture/traffic.db` | таблицы `packets` и `sessions` | DB Browser for SQLite, sql: `SELECT * FROM packets WHERE type='DB_REQUEST'` |
| `capture/traffic.pcap` | дамп трафика с синтетическими IP/TCP-заголовками | **Wireshark**: `tcp.port == 9000` |
| `capture/reports/sessions_*.csv` | сессии (Excel, разделитель `;`) | Excel / LibreOffice |
| `capture/reports/commands_*.csv` | частотность команд/методов | Excel / LibreOffice |
| `capture/clients/client_<ip>.log` | читаемые логи по клиенту (если включено) | текстовый редактор |

CSV-отчёты также формируются автоматически при остановке сниффера
(Ctrl+C) и по кнопке в панели.

## 6. Тревоги

Правила задаются в `config.json → alerts.rules`. Поля правила:

```json
{
  "name": "Откат безналичной оплаты",
  "severity": "crit",                          // info | warn | crit
  "match": {"method_type": "CASHLESS_ROLLBACK"}, // точные совпадения полей пакета (AND)
  "size_gt": 100000,                            // опц.: размер больше N
  "size_lt": null,                              // опц.: размер меньше N
  "keyword": "declined",                        // опц.: подстрока в данных
  "threshold": {"count": 3, "window_sec": 60},  // опц.: сработать при N за окно
  "actions": ["console", "web", "sound", "webhook", "file"]
}
```

Доступные поля для `match`: `protocol`, `msg_type`, `method_type`, `method`,
`cmd_type`, `cmd_class`, `cmd`, `client`, `port_name` — любые из пакета.

Готовые правила в конфиге по умолчанию:

1. **Thrift EXCEPTION** — сервер вернул исключение.
2. **Откат безналичной оплаты** — 2+ `CASHLESS_ROLLBACK` за минуту.
3. **Гигантский пакет** — пакет больше 1 МБ.
4. **Ошибка БД в запросе** — слово «error» в DB_REQUEST.

Дополнительно:

- `alerts.silence_sec` — тревога «клиент молчит N секунд» (проверка активных сессий);
- `alerts.webhook_url` — POST `{type:"sniffer_alert", alert:{...}}` на ваш URL
  (Telegram-бот, Zabbix, корпоративный мессенджер);
- `alerts.cooldown_sec` — пауза между повторными срабатываниями одного правила;
- журнал тревог дублируется в `capture/alerts.jsonl`.

## 7. Конфигурация

Файл `config.json` (создаётся командой `--make-config`, см. раздел 1).

### Порты: три способа настроить под себя

1. **`config.json`** (основной способ) — секция `ports` (пары
   `listen`/`target_port`, для каждой можно задать `name` и `parser`) и
   `web.port`. Изменения действуют после перезапуска сниффера
   (для службы — `--service restart`).
2. **Ключ `--ports`** — задать пары поверх конфига:
   `--ports 3003:3004,10010:10011 --target-host 10.0.0.5`.
   Формат: `слушать:цель,слушать:цель`; если цель не указана (просто `3003`),
   целью считается порт+1.
3. **Ключ `--web-port N`** — порт веб-панели поверх конфига.

По умолчанию выбраны нейтральные порты 9000→9001, 9010→9011 (прокси) и
9500 (панель) — чтобы не пересекаться с типовыми сервисами на сервере.
Сценарий АЗС (3003/10010) задаётся явно, как в разделе 1.

Ключи конфигурации:

| секция | ключ | описание |
|--------|------|----------|
| `listen_host` | | интерфейс слушателей (`0.0.0.0` — все) |
| `ports[]` | `listen` | порт, который слушает сниффер |
| | `target_host`, `target_port` | куда перенаправлять трафик |
| | `name` | человекочитаемое имя канала |
| | `parser` | `auto` (детект) или имя парсера (`thrift`, `remote_server`, `modbus`, `json_http`, `hexdump`) |
| `web` | `enabled`, `host`, `port` | веб-панель |
| `console` | `enabled`, `colors`, `verbosity` | вывод в консоль |
| `detection` | `mode`, `fallback` | автодетект; резервный парсер |
| `buffers` | `recv_size`, `connect_timeout` | размер приёма, таймаут подключения к цели |
| `storage` | `dir`, `jsonl*`, `sqlite*`, `pcap*`, `csv_reports`, `text_logs_per_client` | экспорт (см. раздел 5) |
| `alerts` | `rules[]`, `cooldown_sec`, `webhook_url`, `silence_sec`, `alerts_file` | тревоги (см. раздел 6) |

Горячая перезагрузка (кнопка в панели или сохранение файла — сниффер
подхватывает сам): правила тревог, уровень консоли, webhook.
Требуют перезапуска: порты, веб-панель, экспорт-пути.

## 8. Свои парсеры (плагины)

Положите `.py`-файл в папку `plugins/` рядом со `sniffer.py`:

```python
# plugins/my_protocol.py
import struct
from parsers import BaseFramer, FrameError

NAME = "my_protocol"
LABEL = "Мой протокол"
PRIORITY = 60

def detect(chunk, ctx):
    if len(chunk) < 4:
        return 0
    if chunk[:4] == b"MYPR":
        return 90
    return 0

def create_framer(ctx):
    return MyFramer()

class MyFramer(BaseFramer):
    def try_extract(self):
        if len(self.buf) < 8:
            return None
        n = struct.unpack("<I", self.buf[4:8])[0]
        if len(self.buf) < 8 + n:
            return None
        frame, self.buf = self.buf[:8 + n], self.buf[8 + n:]
        return frame

def parse(frame, ctx):
    return {"protocol": "MY_PROTOCOL", "valid": True,
            "summary": "команда %d" % frame[4]}
```

Всё остальное — детект, панель, экспорт, тревоги — подключится само.
`BaseFramer` уже умеет копить частичные данные и резать кадры; для
«некадровых» протоколов не определяйте `create_framer` — парсер будет
получать чанки целиком.

## 10. Частые вопросы

**Порт уже занят.** Другое приложение слушает тот же порт либо сниффер
запущен дважды. Проверьте: `netstat -ano | findstr :9000` (Windows) /
`ss -tlnp | grep 9000` (Linux) и смените порт в конфиге или ключом `--ports`.

**Брандмауэр Windows** при первом запуске спросит разрешение — разрешите
доступ из сети АЗС к портам сниффера и к 9500 (панель).

**Панель не открывается с другого компьютера.** Убедитесь, что `web.host =
0.0.0.0` и порт 9500 открыт в файрволе; открывайте `http://<ip-сервера>:9500/`.

**Пакеты идут, но всё RAW.** Нестандартный протокол — напишите плагин
(раздел 8) или оставьте hex-режим: данные всё равно пишутся в PCAP/JSONL.

**Тормозит панель при потоке >1000 пак/с.** Включите паузу или сузьте
фильтры; таблица держит 800 строк, буфер хранения — 5000 пакетов.

**Вишик не видит трафик в PCAP.** Файл открывается как RAW IP;
используйте фильтр `tcp.port == 9000` (или порт вашего канала). Синтетические
IP-адреса: клиент — реальный, сервер — 127.0.0.1/цель из конфига.

**SQLite заблокирован другой программой.** Закройте DB Browser на время
работы сниффера или выключите sqlite в конфиге.

**Служба ставится с ошибкой Access denied.** Установка/удаление/запуск
службы требуют прав администратора: запускайте cmd/bat «от имени
администратора» или положитесь на автоподнятие в `service.bat`.

**Служба запущена, а панели/пакетов нет.** Смотрите `capture\service.log`
и журнал Windows (Просмотр событий → Журналы Windows → Система/Приложение);
частая причина — занятый порт или ошибка в конфиге: проверьте конфиг
командой `... --check-config`.

## 11. Автозапуск на Linux (systemd)

`/etc/systemd/system/universal-sniffer.service`:

```ini
[Unit]
Description=Universal Sniffer (TCP proxy + web panel)
After=network.target

[Service]
Type=simple
ExecStart=/usr/bin/python3 /opt/universal_sniffer/sniffer.py --config /opt/universal_sniffer/config.json
WorkingDirectory=/opt/universal_sniffer
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Установка и управление:

```
sudo systemctl daemon-reload
sudo systemctl enable --now universal-sniffer
systemctl status universal-sniffer
journalctl -u universal-sniffer -f        # живые логи
```
