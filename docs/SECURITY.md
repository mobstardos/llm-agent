# Безопасность и контроль

Безопасность заложена в архитектуру с самого начала — это критически важный слой.
Разрешать AI-агенту напрямую изменять файлы и базы данных — огромный риск.

---

## Принципы

### Принцип минимальных привилегий

Каждый агент и MCP-сервер получает ровно те права, которые нужны для задачи.
Агенты БД по умолчанию работают в режиме read-only.

### Human-in-the-Loop (HITL)

Любая разрушительная операция (удаление файла, `DROP TABLE`, `DELETE` без `WHERE`,
изменение данных в 1С) должна требовать явного подтверждения от пользователя.

### Sandboxing

Все файловые операции ограничены корневой директорией проекта.
Для опасных команд и SQL-запросов можно использовать изолированные окружения (Docker).

### Аудит и логирование

Каждое действие агента, каждый вызов инструмента и каждый SQL-запрос логируются.
Это необходимо для отладки и разбора инцидентов.

### Транзакционность и откат

Все изменения в БД — в транзакциях. Для файловых операций — использование
системы контроля версий (Git) для возможности отката.

---

## Список операций, требующих подтверждения

Задаётся в `config/settings.yaml` в секции `limits.require_confirmation_for`:

- `write_file`
- `apply_patch`
- `execute_write_query`
- `execute_migration`
- `drop_table`
- `delete_rows`

---

## Рекомендации по развёртыванию

1. Использовать отдельного пользователя СУБД с минимальными правами.
2. Не давать агенту доступ к секретам (`.env`, `~/.ssh`, ключи).
3. Начинать с read-only и только затем добавлять операции записи.
4. Для shell-команд использовать только Docker/sandbox с allowlist.
5. Регулярно просматривать логи и аудит действий агента.

## Куки веб-чатов (DeepSeek/Qwen) — Task 24-a

Расширение «LLM Agent Bridge» (v1.2.0, permission `cookies`) умеет
забирать куки чатов `chat.deepseek.com` / `chat.qwen.ai` после ручного
входа пользователя и отправлять их на локальный сервер
(`POST /api/bridge/cookies`), который сохраняет их в `.env`
(`DEEPSEEK_*`, `QWEN_WEB_*`). Границы и гарантии:

* куки уходят **только на адрес сервера, настроенный в расширении**
  (по умолчанию `http://127.0.0.1:8000`); внешних сервисов в обмене нет;
* сервер принимает только куки доменов провайдера, аналитический шум
  (`_ga`, `intercom-*`, …) отбрасывается, значения ограничены по длине;
* в статусах (`GET /api/bridge/cookies/status`, отчёт
  `data/bridge/cookies_status.json`, вкладка «Мост») значения никогда
  не отображаются и не пишутся — только факт настройки, имена кук и
  маскированные хвосты (`…abcd (N симв.)`);
* куки хранятся в `.env` наравне с остальными секретами — защищайте
  каталог проекта как защищали бы папку с паролями браузера;
* `DELETE /api/bridge/cookies/{provider}` (и «✕» на вкладке «Мост»)
  затирает переменные провайдера в `.env` и окружении;
* вход выполняется самим пользователем на официальной странице чата —
  расширение не видит и не хранит пароль, только сессионные куки.
