# План внедрения и развития

## 💎 Практический план внедрения

Разворачивайте систему поэтапно — это позволит строить мощный инструмент,
не рискуя данными и кодом на ранних стадиях.

1. **Этап 1. Фундамент и безопасность.**
   Начать с файлового агента и MCP-сервера Filesystem.
   Реализовать строгий sandboxing и механизм подтверждения для операций записи.

2. **Этап 2. Базы данных (только чтение).**
   Подключить агентов MySQL/SQLite и PostgreSQL.
   Дать им только инструменты чтения и исследования схемы — это уже даёт огромную
   пользу для анализа и документирования.

3. **Этап 3. 1С (только чтение).**
   Интегрировать MCP-сервер для 1С. Реализовать инструменты для справочников,
   документов и метаданных.

4. **Этап 4. Операции записи.**
   Только после проверки надёжности чтения — постепенно добавлять инструменты
   изменения данных и схемы. Каждый новый write-инструмент защищён подтверждением.

5. **Этап 5. Оркестрация.**
   Сначала — простой роутинг по правилам. Когда система стабильна — переход
   к LLM-оркестратору для сложных сценариев.

## 🧭 Возможные направления развития

1. **Human-in-the-Loop (approval gate).**
   Список `limits.require_confirmation_for` в `settings.yaml` уже объявлен.
   Осталось реализовать в `MCPManager.call_tool`: при вызове «опасного» инструмента
   отправлять WebSocket-сообщение `approval_request` и ждать ответа пользователя.

2. **История диалога.**
   Сейчас история собирается в `main.py`, но не передаётся дальше.
   Можно прокидывать её в `orchestrator.handle()` для контекста.

3. **Аудит.**
   Логировать шаги агентов в SQLite или файл-журнал.

4. **Retry и таймауты LLM.**
   Обернуть `llm.chat` в retry-стратегию (например, `tenacity`).

5. **Streaming ответов.**
   Использовать `chat.completions.create(stream=True)` и отправлять токены по WS.

6. **Валидация tool-calls.**
   Проверять аргументы tool-вызовов по JSON Schema до вызова MCP.

7. **Замена самописного MCP-сервера 1С на готовый.**
   Проекты `mcp-1c`, `1c-mcp-toolkit`, `1c-odata-mcp` дают более полное покрытие OData 1С.

8. **Плагинная архитектура агентов.**
   Автоматическая регистрация агентов по файлам в `src/agents/` через реестр.
